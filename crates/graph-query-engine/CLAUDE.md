# crates/graph-query-engine

The graph query engine (ADR-0019): the only code that depends on `LadybugDB`. Pod-tools register a materialization (`materialize`) that turns the records under one key into nodes and relations; each identity's graph (`db::GraphCell`) is built from the records an application hands it through a `record::RecordSource` per zone, and read through handles fixed to the pods and zones they were made for (`PodGraph`, `GraphView`). An owner's texts are searched by meaning through `vector::VectorIndex`, an index of its own beside the graph. Spec: mia-docs, `components/mee-pdn/graph-query-engine`.

Deliberately absent: any pod-tool (the registry starts empty, and the tests define their own), any knowledge of mee-pdn's record kinds or membership (an application decides which zones a handle reaches and how it keeps records), writes through a handle, and vectors made by the engine. No type, query or schema of `LadybugDB` crosses the crate's interface.

`LadybugDB` is built from source with its vector extension: `just lbug-vector-source` assembles the tree in `.lbug-src` (`scripts/lbug-vector-source.sh`), the workspace's `.cargo/config.toml` points the lbug crate at it, and `build.rs` links the extension with a link-library directive, so every binary built against the crate, an Android one included, gets it. Without the tree, lbug builds its bundled engine and the vector index has no extension to run on. `tests/bulk_failure.rs` points the temporary directory at a file to fail a bulk load's staging, and is alone in its test binary because of it.
