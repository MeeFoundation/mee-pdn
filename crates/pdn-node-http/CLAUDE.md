# crates/pdn-node-http

The thin HTTP host for the demo stand: an axum binary embedding one runtime. `GET /live` always on; the `/debug/` subtree is scaffolding behind `PDN_DEBUG` set to `1` or `true` (absent when unset, `0` or `false`; any other value stops the start; route names unpinned) and covers identities, the linking ceremony and pods — one route to one service call, with record and operation payloads as raw bodies and everything else as JSON. Every pods route names the identity performing the operation before the pod (`/debug/identities/{identity}/pods/{pod}/…`), because an operation acts for the identity it names and for that one alone (ADR-0013). Refusals arrive as refusals: one closed error table maps the runtime's typed errors to statuses (403 refused, 409 not hosted or no member, 400 malformed, 404 absent, 500 unrecognized). `/debug/status` states the node, `profile release|debug` and `observation on|off`, then the hosted identities.

The `observation` feature (`pdn-node/test-util` under it, off by default, never in the stand's image) adds 3 routes behind `PDN_DEBUG`, one to each of the runtime's test-only observation calls (the observation spec of `pdn-node`): an event stream of JSON Lines, the observed join (the join route's invite; the pod id in the `pdn-pod` header and the event stream as body), and the record listing. Event streams have their own bound of 32, a slot taken before the runtime is called; a request's permit of the 16 is released with its headers; a stream ends with the runtime and at the host's stop signal (`serve`).

Deliberately absent, and to stay absent: any pod store ticket handover (a pod invite carries a one-time secret, and the tickets cross only inside the join dialogue), any raw entry written into a pod's store (forgeries are the data layer's tests), anything that forces reconciliation or resets state, and any handler addressing another host — the crate carries no HTTP client, and inter-node traffic is the runtime's own protocols.

Env: `PDN_POD_RECONCILE_INTERVAL_SECS` (the runtime's pod pass in seconds, a positive whole number, default unset; in every build), `PDN_DATA_DIR` (required — the runtime's storage directory; the host offers no in-memory mode, so unset stops the start naming the variable, and a directory the runtime cannot use — unwritable, held by another running node — stops it the same way, serving neither liveness nor the debug surface), `PDN_HOST` / `PDN_PORT` (default `127.0.0.1:3011`, loopback so a wider bind is deliberate), `PDN_DEBUG` (`1` or `true` serves the `/debug/` subtree, `0`, `false` or unset keeps it off, any other value stops the start), `PDN_ANY_ORIGIN` (the same closed set; on, every `/debug/` answer carries the cross-origin headers the demo's browser screens need, open to any origin, so any page open in a browser on the host reads what the subtree answers; off unless set), `PDN_CONNECTIVITY` (`direct` default, `relays`, or `product` — relays and address lookup, where both ends' node ids are visible to whoever runs the relay). Depends on `pdn-node` only — no direct `data-layer` dependency. With `PDN_ANY_ORIGIN` unset a page of another origin reads nothing of the subtree, but it can still send a request a browser sends without asking (a `POST` with no body or a plain-text one) whose answer it cannot read; a request whose `Host` names anything but an IP literal or `localhost` is refused 421 (`admit_local_host`), so a page made same-origin by DNS rebinding is kept out; the subtree exists only where `PDN_DEBUG` says so, and a host that serves it to a browser it does not trust is the demo's problem to avoid.

Its tests drive the surface across containers and nowhere else (`tests/stand*.rs` over the harness in `tests/common/`): the runtime's own behaviour is proven by `pdn-node`'s scenarios, so a second in-process run of the same flow through HTTP would be a third copy of it. The stand (`ops/Dockerfile`, `just test-docker`, and its own CI job) runs each node as its own process in its own container on one network per test, with HTTP published to the test host and nothing but the runtime's own protocols between nodes. Three tests that build a runtime stay in this process, each for a property of the host that no request on the surface can produce, since none can stall the runtime's coarse state lock: `tests/readiness.rs` holds that lock from inside to show `/live` answering while `/ready` reports the wait, `tests/admission.rs` holds it to keep the `/debug/` ceiling's worth of requests in flight and show the one past it shed, and `tests/streams.rs` (`observation`) holds it beside open event streams for the stream bound and drives the host's stop. The observation routes' scenarios (`tests/stand_observation.rs`) run against a second image built with `FEATURES=observation`. The unit tests in `src/` run in the test process too: each tests one of the host's own functions alone — the error table, the parsers, the environment, the admission function, the runtime budget — and starts no runtime.
