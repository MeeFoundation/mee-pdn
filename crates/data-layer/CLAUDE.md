# crates/data-layer

The data layer over `crates/pdn-store`, our iroh-docs variant: the `SyncNode` stack assembly, the access book that classifies every session (reads filtered on egress, writes judged by the fork's `validate_entry` hook per ADR-0008 — both installed at spawn), the metadata stores, the retraction tracker, and the protocol-agnostic ceremony slot. One node hosts any number of identities, each with a half of the node it owns: its own docs engine, replica store, registry, access book and author (ADR-0013). Every session names the identity whose replica it addresses and the identity its caller acts for, and is judged by the named identity's records alone. Enforcement arms per identity by registration (`host_identity` / `host_connection`) and per replica by the grantee import, and a directory or connection metadata store starts its sync at that arming rather than at its import, since a session started before the book can judge it is refused — `host_connection` also points the own half at the devices the peer half is dialed at, so whichever side arms second reaches the first over both; a data replica no registration covers is refused rather than served, while a directory and a connection metadata store keep the ticket bound Invariants 1 and 3 give them. Ownership runs from `SyncNode` down: every engine gets only the sending end of the node's co-located request channel, and the node's task serving it holds the identity map weakly (`serve_co_located`), so a node dropped without `shutdown` still releases its engines, stores and directory. The ceremony slot — spawn-time registration of externally supplied protocols plus a narrow dial handle — is consumed by pdn-node's two handlers, pairing per ADR-0011 and linking per ADR-0012, and stays protocol-agnostic here because the ceremonies' semantics live in pdn-node.

Stores: the device-replicated `PrivateMetadataStore` (the one directory of an identity's own state — its devices, confirmed and pending, the typed tickets to its other stores, its connections records, its retraction markers — plus the namespace accessor and the bounded catch-up wait the linking ceremony stands on) and the cross-identity `ConnectionMetadataStore` (one replica per connection direction, issuer-written / counterparty-read per Invariant 3, carrying grants keyed by data-store issuer and the issuer's published device set). `forget_namespace` is the rollback counterpart of `import_namespace` — it unregisters the issuer, not just drops the replica — and `undo_import_namespace` is that same act under the name the import's caller undoes by, doing nothing after an import onto the replica its issuer already resolved to, which bound nothing.

The `DataLayer` trait in `layer.rs` is declared and implemented by nothing; the runtime drives `SyncNode` directly.

Storage is a required choice of every spawn (`SpawnOptions::storage`): memory by name — the workspace's suites, via their spawn helpers — or a directory by name, with no default. A configured directory holds everything a node needs to be itself:

```
<directory>/
  node.key                  the endpoint's secret key: the node id survives a restart
  lock                      the running node's exclusive hold; a second node on the directory is refused as DirectoryHeld
  blobs/                    payload bytes, one store for the node
  identities/<identity>/    one identity's half of the node
    docs.redb               its replica store
    default-author          the one author its writes carry
    directory               its hosting record: its directory's namespace, written at the commit point of a create or link
```

Each hosted identity's stores write with that identity's one author (`SyncNode::default_author`, persisted with its replicas), and what one identity's replica store may hold is a share of a node budget, cut as that store opens from the identities `identities/` then records as hosted, this one included — so what an unfinished create or link left takes no share, and no host states a count (`SyncNode::replica_cache_share_bytes`, `replica_cache_budget_exceeded`); `PrivateMetadataStore::open` reopens a directory replica the node already holds — recovery's constructor, beside `create` and `import` — and answers `Ok(None)` for a namespace the store does not hold, so a caller acting on a durable record tells an absent replica from a store that failed to answer.

Reachability is the other spawn-time choice (`SpawnOptions::connectivity`), and the constructor names it rather than the caller assembling it. `Connectivity::Direct` binds nothing beyond the socket — a peer is reached at an address the endpoint publishes about itself or not at all — and it is what `memory` and `on_directory` give the suites and the container stand, whose peers already hold an address for each other. `Connectivity::Relays` adds the relay servers iroh's own `default_relay_mode` names, so a peer behind a NAT is reachable and the relay URL travelling in every ticket and ceremony payload keeps the node dialable after its network changes. `Connectivity::RelaysAndAddressLookup` adds publishing and resolving under the node id, which is what `for_product` gives a node shipped to a device the project does not control: without it a contact carrying a node id alone — a sibling read out of a device record, a peer whose ticket addresses have gone stale — is not dialable at all. The three map onto iroh as `Minimal` with the relay mode set explicitly, twice, and then the `N0` preset whole.

Scenario tests in `tests/`. Capability _semantics_ stay above: tokens are opaque payloads here. Invariants are numbered in `mia-docs/openspec/specs/components/mee-pdn/invariants.md` at the repo root (referenced by number, never name).
